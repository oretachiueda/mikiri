# S001 정정 3: 정정 2 뒤에 찾은 구현 문제와 다시 돌리기

상태: `prereg/S001-eurusd-signal-search.md`(장부 seq 21), 정정 1(seq 22), 정정 2(seq 23)의 정정이다. 탐색 공간, 설정 수, 정의, 비용, 구간, 후보 문턱은 바꾸지 않는다. 정정 2 뒤의 실행 결과를 본 뒤에 쓰므로 본 것을 먼저 적는다.

## 1. 정정 2 뒤의 실행과 본 것

| 실행 | 계산한 설정 | 본 값 | 무효 사유 |
|---|---|---|---|
| 2차 | 246 | 비용 후 SR 중앙값 −0.064, 최고 0.659, Deflated Sharpe ≥ 0.95인 설정 0 | 구현의 중간 결과 캐시가 정정 2의 4시간봉 수정 전에 만들어져, 4시간봉이 여전히 자정에서 쪼개져 있었다 |
| 3차 | 246 | 중앙값 −0.064, 최고 0.659, 0 | 크기 σ̂의 입력(레버리지 없는 비용 전 일수익)이 그날 마감에 들고 있는 포지션만 하루 시작가부터 셌다 |
| 4차 | 246 | 중앙값 −0.057, 최고 0.673, 0 | 금지 구간 때문에 미룬 체결이 잠금으로 이미 0이 된 목표를 넘겨, 원시 신호가 그대로인데도 재진입 잠금이 풀렸다 |

세 실행 모두 결과를 쓰지 않는다. 최종 보고에는 이 값들도 같이 싣는다.

## 2. 찾은 경위

다른 계열 작업자가 문서만 보고 따로 구현한 계산기로 세 설정(일봉 요일 숏 금요일 X2, 4시간 모멘텀 k = 20 X2, 1시간 평균 회귀 n = 5 z₀ = 1.5 X2)을 실제 자료에서 다시 계산해 일수익을 날짜마다 대조했다. 독립 구현 쪽에서 나온 버그(달의 첫 평일을 자료가 있는 첫 날로 본 것, 그날 행이 없을 때 전날 17시 이후 행을 넣지 못한 것)는 독립 구현에서 고쳤다.

## 3. 버그와 따라야 할 규칙

| 버그 | 따라야 할 규칙 |
|---|---|
| 중간 결과 캐시를 고친 코드로 다시 만들지 않았다 | 모든 실행은 원자료에서 고친 코드로 다시 만든 봉을 쓴다 |
| σ̂ 입력 일수익이 장중에 닫힌 거래와 장중 진입의 시작가를 빠뜨렸다 | 정정 1 9번: 그날 보유 구간마다 s × (P_끝 − P_시작) ÷ P_시작의 합 |
| 미룬 체결이 잠금으로 0이 된 목표를 넘겨 잠금을 풀었다 | 정정 1 7·8번: 잠금은 원시 신호가 손절 당시 값과 달라질 때만 풀리고, 미룬 체결에는 원시 신호를 넘긴다 |

해석 하나를 적는다: 2007-07-02의 자산 재설정에서 열린 포지션의 명목은 그대로 둔다(정정 1 12번 "자산만 그날 아침 1로 다시 둔다"의 문자 그대로). 두 구현 모두 이렇게 계산한다.

## 4. 다시 돌리기와 세는 법

- 고친 코드로 246개 설정을 5차로 한 번 더 돌린다. 독립 구현과 세 설정의 일수익이 맞으면 5차 결과가 S001의 결과다. 맞지 않으면 원인을 찾아 이 표에 정정을 더한다.
- 계산 횟수는 따로 센다: 1차~4차 각 246(무효), 5차 246. 정정 2대로 상한 300, Deflated Sharpe의 K(246), 장부 `n_cumulative`에는 서로 다른 설정 수만 넣는다.
